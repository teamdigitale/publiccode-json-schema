# publiccode.yml 1.0 (release candidate)

This branch (`standard-1.0-rc`) adds a schema for **1.0.0**, following the
standard's [`1.0-rc` branch](https://github.com/publiccodeyml/publiccode.yml/tree/1.0-rc)
as of its commit `f3bb7045` (2026-08-25). 1.0 isn't released: its rules can
still change, and `isReleaseCandidate("1")` is `true`.

## What 1.0-rc changes

The standard's branch only removes things. On top of 0.8:

| Change (1.0-rc commit) | In the 1.0.0 schema |
|---|---|
| Deprecated keys removed (#325): `monochromeLogo`, `inputTypes`, `outputTypes`, `description.[lang].genericName`, `legal.repoOwner`, `legal.authorsFile`; uppercase country codes only; YAML 1.2 | the keys are unknown fields (errors); `intendedAudience.countries` and `unsupportedCountries` are `^[A-Z]{2}$` |
| `government` scope removed (#305) | not in the `scope` enum |
| Deprecated Italian keys and then the country-specific sections removed (#316, `f3bb7045`) | no `IT` / `it` section: use `organisation` and `supports` |
| E.164 required for `maintenance.contacts[].phone` (#306) | `pattern: ^\+[1-9][0-9]{1,14}$` |

`publiccodeYmlVersion` is `"1"`, `"1.0"` or `"1.0.0"` (the Go parser's
`PublicCodeV1` skeleton, not enabled yet, accepts `"1"`).

**Not decided by the standard yet**: the 1.0-rc branch was cut before 0.8 and
is 72 commits behind `main`, so the keys 0.8 deprecated (`usedBy`, `videos`,
`unsupportedCountries`, `dependsOn.open`, the single string `isBasedOn`) are
still there, deprecated. Nor are the changes on `main` after 0.8 (optional
`features`, the `building-information-modelling` category) in it.

## How the library models it

- `FieldHistory.removed`, `ValueHistory.removed` and `CountrySection.removed`:
  the first version without a key, a value or a section. The schema builder
  drops them from that version on, like it drops keys before their `since`.
- `validateVersion()` against 1.x is always strict: there are no lenient v1
  rules like the parser's v0. The keys 0.x deprecated are errors there, so
  they aren't repeated as deprecation warnings. `validate()` stays v0-only.
- `upgrade(data, { to: "1.0.0" })` applies every fix up to 1.0.0 and a new
  rule, `phoneE164`: it drops separators from numbers with an international
  prefix (`+39 06 1234 5678` → `+390612345678`, `0039…` → `+39…`); a number
  with no prefix is left for a manual fix. The `government` scope, as before,
  needs `lossy: true`.
- `RELEASE_CANDIDATES` and `isReleaseCandidate()`, so that UIs can label 1.0.0
  as not final. `LATEST_KNOWN` stays 0.8.0.
